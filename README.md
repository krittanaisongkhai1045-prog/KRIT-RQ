# Inspection Desk

เว็บทำใบส่งตรวจงานก่อสร้าง (CM OPEN / CM CLOSE) พร้อมแบบทำสีขอบเขต รูปตรวจที่เขียนคอมเมนต์ได้ เลขที่ DEFECT และตำแหน่งกระเบื้องที่ต้องแก้
ข้อมูลเก็บใน **Supabase** ทุกคนเปิดดูได้ แก้ไขได้เฉพาะบัญชีเจ้าของ เว็บเป็นไฟล์ static (HTML/CSS/JS ธรรมดา ไม่มี build step) ใช้ **GitHub Pages** เผยแพร่

## โครงสร้าง

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | หน้าเว็บ โหลดสคริปต์ตามลำดับ |
| `config.js` | ใส่ Supabase URL และ anon key |
| `css/app.css` | หน้าตาเว็บ (ธีมสว่าง/มืดตามระบบ) |
| `js/core.js` | ค่าเริ่มต้น (checklist, ประเภท DEFECT), ตัวช่วยรูป, วาดโซน/หมุด/ลูกศรบนรูป (`openBoard`) |
| `js/storage.js` | การเก็บข้อมูล: Supabase (`cloud`) หรือ IndexedDB ในเครื่อง (`local`), ล็อกอิน, realtime |
| `js/views.js` | หน้ารายการ, หน้าใบตรวจ (แท็บข้อมูล/แบบ/รูป/DEFECT/เอกสาร), ตั้งค่า |
| `js/report.js` | สร้างหน้า A4: ใบปะหน้า, หน้าแบบ (แนวนอน/แนวตั้งตามแบบ), ใบ DEFECT, หน้ารูป, ส่งออก PDF/HTML |
| `js/app.js` | การคลิก/พิมพ์, สำรอง-กู้ข้อมูล, เริ่มระบบ |
| `supabase/schema.sql` | ตาราง, สิทธิ์ (RLS), Realtime, bucket รูป |
| `assets/` | โลโก้และลายเซ็นเริ่มต้น (แทนด้วยไฟล์ของคุณได้ หรือเปลี่ยนในหน้า “ตั้งค่า”) |

## ตั้งค่า (ทำครั้งเดียว)

### 1. Supabase
1. สร้างโปรเจกต์ที่ https://supabase.com
2. **SQL Editor** → เปิดไฟล์ `supabase/schema.sql` → แก้ `YOUR_EMAIL@example.com` เป็นอีเมลของคุณ → กด Run
3. **Authentication → Users → Add user** ใส่อีเมลเดียวกันกับข้อ 2 พร้อมรหัสผ่าน และติ๊ก *Auto Confirm User*
4. **Authentication → Sign In / Providers** ปิด *Allow new users to sign up* (กันคนอื่นสมัครบัญชีเข้ามา ถึงสมัครได้ก็แก้ข้อมูลไม่ได้เพราะไม่อยู่ใน `app_owners`)
5. **Project Settings → API** คัดลอก *Project URL* และ *anon public key*

### 2. ใส่ค่าในเว็บ
แก้ `config.js`:
```js
window.APP_CONFIG = {
  SUPABASE_URL: 'https://xxxx.supabase.co',
  SUPABASE_ANON_KEY: 'eyJ...'
};
```
anon key เปิดเผยได้ ความปลอดภัยอยู่ที่ RLS ใน `schema.sql` (ห้ามใส่ `service_role` key ในไฟล์นี้)

### 3. GitHub Pages
1. Push โค้ดขึ้น branch `main`
2. **Settings → Pages → Build and deployment → Source: GitHub Actions**
3. workflow `.github/workflows/pages.yml` จะเผยแพร่เองทุกครั้งที่ push ลิงก์อยู่ใน Actions หรือหน้า Pages

### 4. ใช้งาน
- ทุกคนเปิดลิงก์ดูได้ (ป้าย “ดูอย่างเดียว”) เห็นข้อมูลที่เจ้าของบันทึกทันที ดาวน์โหลด PDF ได้
- เจ้าของกด **เข้าสู่ระบบผู้แก้ไข** (มุมบนขวา) ด้วยอีเมล/รหัสผ่านจากข้อ 1.3 แล้วแก้ไขได้ทันที

## ย้ายข้อมูลจากเวอร์ชันเก่า (หน้า Artifact)
ในเว็บเก่ากด **ตั้งค่า → สำรองข้อมูลทั้งหมด (.json)** แล้วในเว็บใหม่ (ล็อกอินเจ้าของ) กด **ตั้งค่า → กู้ข้อมูลจากไฟล์**

## ทดลองในเครื่อง
เปิดโฟลเดอร์ด้วยเซิร์ฟเวอร์ static เช่น `python3 -m http.server 8000` แล้วเข้า http://localhost:8000
(ถ้า `config.js` ว่าง จะเป็นโหมดเก็บในเบราว์เซอร์นี้ และมีข้อมูลตัวอย่างให้ลอง)

## หมายเหตุ
- เอกสารทุกใบ (project/library/request/defect) เก็บเป็น JSON ในตาราง `docs` ขนาดต่อเอกสารควรไม่เกิน ~250 KB (เส้นที่วาดบนรูปจำนวนมากทำให้ใหญ่ได้)
- รูปเก็บใน bucket `inspection-images` (สาธารณะ) ชื่อไฟล์คือ id ของรูป การลบรูปออกจากใบจะไม่ลบไฟล์ใน bucket อัตโนมัติ
- การส่งออก PDF ทำในเบราว์เซอร์ด้วย html2canvas + jsPDF

## ฟีเจอร์เพิ่มเติม

### QC Before / After (ไม่ต้องมีใบ Inspection)
แท็บ **QC Before/After** ใช้บันทึก DEFECT ที่พบจากการตรวจ QC โดยไม่ผูกกับใบส่งตรวจ
- ถ่ายรูป BEFORE → แก้ไข → ถ่ายรูป AFTER → ปิด (สถานะ: ต้องแก้ไข / แก้แล้ว รอตรวจซ้ำ / ผ่าน QC ปิดแล้ว)
- เขียน/ลูกศร/วงกลมบนรูปได้ ระบุแผ่นกระเบื้องที่ต้องแก้ ปักหมุดตำแหน่งบนแบบหน้างาน
- จัดกลุ่มตามอาคาร / ห้อง / ประเภท, ค้นหา, กรองตามสถานะ
- ปุ่ม PDF / HTML สร้างรายงาน Before/After แนวนอน (1 จุดต่อ 1 หน้า พร้อมแบบย่อและจุดซูม) ตามตัวกรองที่เลือกอยู่
- ข้อมูลเก็บในตาราง `docs` เดิม (collection `defects`, ฟิลด์ `qc:true`) ไม่ต้องแก้ SQL

### แบบหน้างาน (ฉบับปัจจุบัน)
- เจ้าของอัปโหลดแบบ (รูป/PDF) ตั้งชื่อ, Rev., วันที่, กลุ่ม (เช่น อาคาร A / ชั้น 3)
- “อัปโหลดฉบับใหม่” แทนรูปแบบเดิมโดยคงโซนและหมุด (ถ้าสัดส่วนรูปต่างกันจะมีคำเตือน)
- เจ้าของวาดโซนสีและปักหมุด QC บนแบบได้ ทุกคนเห็นผลเดียวกัน
- ทีมงานที่ไม่ได้ล็อกอินเปิดดู ซูม และขีดเขียน/วางโซนของตัวเองได้ (เก็บในเบราว์เซอร์เครื่องนั้น ไม่ส่งถึงคนอื่น) และกด “บันทึกเป็นรูป” เพื่อแชร์ต่อ
