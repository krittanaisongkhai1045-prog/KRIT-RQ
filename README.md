# Inspection Desk

เว็บทำใบส่งตรวจงานก่อสร้าง (CM OPEN / CM CLOSE) พร้อมแบบทำสีขอบเขต รูปตรวจที่เขียนคอมเมนต์ได้ เลขที่ DEFECT และตำแหน่งกระเบื้องที่ต้องแก้
ข้อมูลเก็บใน **Supabase** เจ้าของแต่ละเอกสารกำหนดสิทธิ์อ่าน/แก้ไขได้เอง เว็บเป็นไฟล์ static (HTML/CSS/JS ธรรมดา ไม่มี build step) ใช้ **GitHub Pages** เผยแพร่

## โครงสร้าง

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | หน้าเว็บ โหลดสคริปต์ตามลำดับ |
| `config.js` | ใส่ Supabase URL และ anon key |
| `css/app.css` | หน้าตาเว็บ (ธีมสว่าง/มืดตามระบบ) |
| `js/core.js` | ค่าเริ่มต้น (checklist, ประเภท DEFECT), ตัวช่วยรูป, วาดโซน/หมุด/ลูกศรบนรูป (`openBoard`) |
| `js/storage.js` | การเก็บข้อมูล: Supabase (`cloud`) หรือ IndexedDB ในเครื่อง (`local`), ล็อกอิน, realtime |
| `js/views.js` | หน้ารายการ, หน้าใบตรวจ (แท็บข้อมูล/แบบ/รูป/DEFECT/เอกสาร), ตั้งค่า |
| `js/report.js` | สร้างหน้า A4: ใบปะหน้า, หน้าแบบ (แนวนอน/แนวตั้งตามแบบ), ใบ DEFECT, หน้ารูป, ส่งออก PDF/HTML |
| `js/app.js` | การคลิก/พิมพ์, สำรอง-กู้ข้อมูล, เริ่มระบบ |
| `supabase/schema.sql` | ตาราง, สิทธิ์ (RLS), Realtime, bucket รูป |
| `assets/` | โลโก้และลายเซ็นเริ่มต้น (แทนด้วยไฟล์ของคุณได้ หรือเปลี่ยนในหน้า “ตั้งค่า”) |

## ตั้งค่า (ทำครั้งเดียว)

### 1. Supabase
1. สร้างโปรเจกต์ที่ https://supabase.com
2. **SQL Editor** → เปิดไฟล์ `supabase/schema.sql` → ตรวจว่าอีเมลแอดมินในบรรทัด `insert into public.app_owners` เป็นของคุณ → กด Run
   (ไฟล์นี้ใหม่กว่าเวอร์ชันก่อน ถ้าเคยรันของเก่าแล้ว รันซ้ำได้ ตาราง `docs` จะถูกเพิ่มคอลัมน์สิทธิ์ให้เอง ข้อมูลเดิมยังอยู่ — ดู “อัปเกรดจากสคีมาเก่า” ด้านล่าง)
3. **Authentication → Users → Add user** สร้างบัญชีสมาชิก: ตัวคุณ (อีเมลแอดมิน) และทีมงานที่ต้องสร้าง/แก้เอกสาร ใส่อีเมลกับรหัสผ่าน และติ๊ก *Auto Confirm User*
4. **Authentication → Sign In / Providers** ปิด *Allow new users to sign up* (เฉพาะคนที่คุณสร้างบัญชีให้เท่านั้นที่เป็นสมาชิก)
5. **Project Settings → API** คัดลอก *Project URL* และ *anon public key*

### 2. ใส่ค่าในเว็บ
แก้ `config.js`:
```js
window.APP_CONFIG = {
  SUPABASE_URL: 'https://xxxx.supabase.co',
  SUPABASE_ANON_KEY: 'eyJ...'
};
```
anon key เปิดเผยได้ ความปลอดภัยอยู่ที่ RLS ใน `schema.sql` (ห้ามใส่ `service_role` key ในไฟล์นี้)

### 3. GitHub Pages
1. Push โค้ดขึ้น branch `main`
2. **Settings → Pages → Build and deployment → Source: GitHub Actions**
3. workflow `.github/workflows/pages.yml` จะเผยแพร่เองทุกครั้งที่ push ลิงก์อยู่ใน Actions หรือหน้า Pages

### 4. ใช้งานและสิทธิ์
- **ผู้ไม่ได้ล็อกอิน**: ดูได้เฉพาะเอกสารที่เจ้าของเปิดเป็น “ทุกคนอ่านได้” และดาวน์โหลด PDF ได้
- **สมาชิก** (ล็อกอินแล้ว): สร้างเอกสารได้ ผู้สร้างเป็น **เจ้าของเอกสาร**
- **เจ้าของเอกสาร** กดปุ่ม **สิทธิ์การเข้าถึง** ที่หัวเอกสารเพื่อกำหนด
  - ใครอ่านได้: ทุกคน / สมาชิกที่ล็อกอิน / เฉพาะอีเมลที่ระบุ
  - ใครแก้ไขได้: ระบุอีเมล (แก้เนื้อหา เปลี่ยนสถานะ สร้างรอบส่งซ้ำ เพิ่ม DEFECT ได้ แต่เปลี่ยนสิทธิ์หรือลบเอกสารหลักไม่ได้)
- เจ้าของและผู้ได้สิทธิ์แก้ไข **เปลี่ยนสถานะได้ตลอด** (ใบตรวจ: ร่าง/ส่งตรวจแล้ว/ผ่าน/ไม่ผ่าน/ยกเลิก, QC: ต้องแก้ไข/แก้แล้ว/ปิด, DEFECT: ผ่าน/ไม่ผ่านรายจุด)
- **แอดมิน** (อีเมลในตาราง `app_owners`) แก้ “ข้อมูลโครงการ / ตั้งค่า” ได้เพียงผู้เดียว และจัดการได้ทุกเอกสาร
- “เอกสาร” หนึ่งชุด = ชุดใบตรวจ (OPEN + รอบส่งซ้ำ + DEFECT ทั้งหมดของชุดนั้น), QC DEFECT 1 จุด, หรือแบบหน้างาน 1 แผ่น — สิทธิ์ใช้ร่วมกันทั้งชุด
- เลขที่ใบตรวจและเลข QC ออกโดยเซิร์ฟเวอร์ (ไม่ซ้ำแม้หลายคนสร้างพร้อมกัน) แอดมินตั้งเลขถัดไปได้ที่ ตั้งค่า → เลขที่ใบตรวจ

## ย้ายข้อมูลจากเวอร์ชันเก่า (หน้า Artifact)
ในเว็บเก่ากด **ตั้งค่า → สำรองข้อมูลทั้งหมด (.json)** แล้วในเว็บใหม่ (ล็อกอินเป็นสมาชิก/แอดมิน) กด **ตั้งค่า → กู้ข้อมูลจากไฟล์**

## ทดลองในเครื่อง
เปิดโฟลเดอร์ด้วยเซิร์ฟเวอร์ static เช่น `python3 -m http.server 8000` แล้วเข้า http://localhost:8000
(ถ้า `config.js` ว่าง จะเป็นโหมดเก็บในเบราว์เซอร์นี้ และมีข้อมูลตัวอย่างให้ลอง)

## หมายเหตุ
- เอกสารทุกใบ (project/library/request/defect) เก็บเป็น JSON ในตาราง `docs` ขนาดต่อเอกสารควรไม่เกิน ~250 KB (เส้นที่วาดบนรูปจำนวนมากทำให้ใหญ่ได้)
- รูปเก็บใน bucket `inspection-images` (สาธารณะ) ชื่อไฟล์คือ id ของรูป การลบรูปออกจากใบจะไม่ลบไฟล์ใน bucket อัตโนมัติ
- การส่งออก PDF ทำในเบราว์เซอร์ด้วย html2canvas + jsPDF

## ฟีเจอร์เพิ่มเติม

### QC Before / After (ไม่ต้องมีใบ Inspection)
แท็บ **QC Before/After** ใช้บันทึก DEFECT ที่พบจากการตรวจ QC โดยไม่ผูกกับใบส่งตรวจ
- ถ่ายรูป BEFORE → แก้ไข → ถ่ายรูป AFTER → ปิด (สถานะ: ต้องแก้ไข / แก้แล้ว รอตรวจซ้ำ / ผ่าน QC ปิดแล้ว)
- เขียน/ลูกศร/วงกลมบนรูปได้ ระบุแผ่นกระเบื้องที่ต้องแก้ ปักหมุดตำแหน่งบนแบบหน้างาน
- จัดกลุ่มตามอาคาร / ห้อง / ประเภท, ค้นหา, กรองตามสถานะ
- ปุ่ม PDF / HTML สร้างรายงาน Before/After แนวนอน (1 จุดต่อ 1 หน้า พร้อมแบบย่อและจุดซูม) ตามตัวกรองที่เลือกอยู่
- ข้อมูลเก็บในตาราง `docs` เดิม (collection `defects`, ฟิลด์ `qc:true`) ไม่ต้องแก้ SQL

### แบบหน้างาน (ฉบับปัจจุบัน)
- เจ้าของอัปโหลดแบบ (รูป/PDF) ตั้งชื่อ, Rev., วันที่, กลุ่ม (เช่น อาคาร A / ชั้น 3)
- “อัปโหลดฉบับใหม่” แทนรูปแบบเดิมโดยคงโซนและหมุด (ถ้าสัดส่วนรูปต่างกันจะมีคำเตือน)
- เจ้าของวาดโซนสีและปักหมุด QC บนแบบได้ ทุกคนเห็นผลเดียวกัน
- ทีมงานที่ไม่ได้ล็อกอินเปิดดู ซูม และขีดเขียน/วางโซนของตัวเองได้ (เก็บในเบราว์เซอร์เครื่องนั้น ไม่ส่งถึงคนอื่น) และกด “บันทึกเป็นรูป” เพื่อแชร์ต่อ

### อัปเกรดจากสคีมาเก่า (ถ้าเคยรัน schema.sql เวอร์ชันก่อนสิทธิ์ต่อเอกสาร)
รัน `supabase/schema.sql` ฉบับใหม่ทั้งไฟล์ แล้วรันคำสั่งนี้ครั้งเดียวเพื่อแยกคลังแบบเดิมเป็นแถวต่อแผ่น และตั้งกลุ่มเอกสารให้ข้อมูลเดิม
```sql
update public.docs set grp = coalesce(data->>'rootId', id) where grp = '' and collection in ('requests','defects');
update public.docs set grp = id where grp = '' and collection <> 'meta';
update public.docs set owner_email = (select email from public.app_owners limit 1) where owner_email is null;
insert into public.docs (collection, id, data, grp)
  select 'plans', item->>'id', item, item->>'id'
  from public.docs, jsonb_array_elements(data->'items') item
  where collection = 'meta' and id = 'library'
on conflict do nothing;
delete from public.docs where collection = 'meta' and id = 'library';
```
(เอกสารเดิมไม่มีเจ้าของที่เป็นสมาชิก แอดมินยังจัดการได้ทุกใบ และตั้งสิทธิ์ให้ทีมได้)

## ฟีเจอร์ในใบตรวจ
- **ประเภทการส่งตรวจกำหนดเองได้**: ตั้งค่า → ประเภทการส่งตรวจ (เช่น `CM OPEN | open`, `CM CLOSE | close`, `Pre-Inspection | open`) และพิมพ์ชื่อประเภทเองในแต่ละใบได้
- **แบบสำหรับใบปะหน้าแยกจากแบบแนบ**: แท็บ “แบบ / ขอบเขต” มีส่วน “แบบสำหรับใบปะหน้า” ของตัวเอง ทำโซนสีแยกจากแบบที่แนบท้ายเอกสาร
- **ช่องลงนาม** 3 ช่อง (ผู้ขอตรวจ / Site Engineer / CC) ชื่อ ตำแหน่ง วันที่ และลายเซ็นภาพได้ทุกช่อง


## แบบหน้างาน: รายการไฟล์ และ DWG

- อัปโหลด PDF หลายหน้า (สูงสุด 40 หน้า) จะแสดงเป็น **1 แถวต่อ 1 ไฟล์** กดเปิดไฟล์เพื่อดูทีละหน้า แก้ชื่อ/Rev./วันที่/กลุ่ม ใช้กับทั้งไฟล์ และสิทธิ์การเข้าถึงเป็นชุดเดียวกัน
- ไฟล์ **DWG / DXF** เก็บไว้ให้ดาวน์โหลด (จำกัด 45 MB ต่อไฟล์ตามแพ็กเกจฟรีของ Supabase) เบราว์เซอร์แสดง DWG ไม่ได้ จึงให้ส่งออกเป็น PDF/รูปแล้วกด “ใส่ภาพแบบ” หรืออัปโหลดพร้อมกันโดยตั้งชื่อไฟล์เหมือนกัน (เช่น `PlanA.dwg` + `PlanA.pdf`) ระบบจะจับคู่ให้
- ไฟล์สำรอง (backup) ในโหมดคลาวด์ไม่รวมไฟล์ DWG เพราะอยู่บน Supabase Storage อยู่แล้ว
- รูป DEFECT ที่แสดงในรายการ DEFECT ของรายงานแล้ว จะไม่ซ้ำในหน้า “รูปประกอบการตรวจสอบ”
- ข้อมูลเดิมที่อัปโหลดไว้ใช้ต่อได้ (แต่ละรายการเดิมกลายเป็นไฟล์ 1 หน้า) ไม่ต้องรัน SQL เพิ่ม


## โหมดหน้างาน (สัญญาณอ่อน / ไม่มีสัญญาณ)

1. **ก่อนเข้าพื้นที่ (ตอนยังมีเน็ต)** กดปุ่ม **“เข้าหน้างาน”** มุมบน → “เตรียมข้อมูลลงเครื่อง” ระบบจะส่งงานที่ค้าง โหลดข้อมูลล่าสุด เก็บรูป/แบบทั้งหมดลงเครื่อง และแคชตัวแอป
2. **ที่หน้างาน** เปิดแอปได้ทันทีจากข้อมูลในเครื่อง (ไม่รอเครือข่าย) ปักหมุด ถ่ายรูป แก้ไขได้ตามปกติ ทุกอย่างบันทึกในเครื่องก่อน
3. **เมื่อมีสัญญาณกลับมา** ระบบส่งขึ้น Supabase เอง (ลองใหม่เรื่อยๆ เมื่อสัญญาณอ่อน) แล้วโหลดข้อมูลล่าสุดของทีมมาแทน มุมบนแสดงสถานะ “รอส่ง…”
- รูปที่ถ่ายหน้างานเก็บในเครื่องจนอัปโหลดสำเร็จ ปิดแอปแล้วเปิดใหม่ก็ยังอยู่
- ข้อควรระวัง: เลขที่เอกสารที่สร้างตอนออฟไลน์เป็นเลขชั่วคราวจากเครื่อง อาจซ้ำกับคนอื่น ตรวจหลังซิงก์; ถ้าแก้เอกสารเดียวกันพร้อมคนอื่น ฉบับที่ส่งทีหลังจะทับ
- บน iPad ควร “เพิ่มไปยังหน้าจอโฮม” (Safari) เพื่อให้ iPadOS ไม่ล้างข้อมูลในเครื่อง และเตรียมข้อมูลใหม่ทุกครั้งก่อนออกหน้างาน
- แอปอัปเดตผ่านตัวแคช: หลังอัปโหลดโค้ดใหม่ขึ้น GitHub ต้องเปิดแอปสองครั้ง (ครั้งแรกโหลดฉบับใหม่ ครั้งที่สองจึงใช้ฉบับใหม่)


## ใบ OPEN / CLOSE, DEFECT แบบโซน, จัดหมวดตามห้อง

- **ใบ OPEN** ไม่มีแท็บรายการ DEFECT (แนบแบบ/แนบรูปได้) และปักหมุด DEFECT บนแบบไม่ได้ — ข้อมูลเก่าที่ OPEN มี DEFECT อยู่แล้วยังเห็นแท็บเดิม · กด “สร้างใบส่งปิด (CLOSE)” จาก OPEN ได้ทันที
- **ใบ CLOSE** ต้องมีรายการ DEFECT (ถ้าไม่มีจะเตือนในแท็บ “เอกสารพร้อมส่ง”)
- **DEFECT แบบโซน**: ในหน้าแก้ไข DEFECT ติ๊ก “DEFECT แบบโซน” ใส่จำนวนแผ่น/ขอบเขต แล้วระบายหลายช่องในผังกระเบื้องด้วยการลาก หรือใช้ปุ่ม เลือกทั้งผัง / เลือกช่วง แถว-คอลัมน์ → 1 รายการแทนหลายสิบแผ่น
- **จัดหมวดตามห้อง**: ใช้ช่อง “ห้อง / พื้นที่” ของ DEFECT จัดกลุ่มในแท็บ DEFECT หน้ารวม DEFECT และใบรายงาน (มีแถบหัวห้องและยอดแผ่นรวมของโซน)
- **แบบที่แนบ** เรียงตามชื่ออัตโนมัติ (E101, E102, E103 … เรียงเลขถูกต้อง ไม่ใช่ E1, E10, E2)
- **เลือกแบบจากคลัง**: เลือกไฟล์ที่เคยอัปโหลด (จัดตามไฟล์/กลุ่ม) → เลือกหน้าที่จะแนบได้หลายหน้า

## ลำดับเอกสารส่งเปิด / ส่งปิด

- **ส่งเปิด (OPEN):** ใบปะหน้า → รูปสภาพหน้างานก่อนตรวจ (≥4 รูป) → แบบ/ขอบเขต
- **ส่งปิด (CLOSE):** ใบปะหน้า → รูปตอนตรวจเปิด (ดึงจากใบ OPEN อัตโนมัติ ติ๊กเอารูปออกได้ที่แท็บรูป) → แบบพร้อมตำแหน่ง DEFECT → รายการ DEFECT พร้อมรูปแต่ละรายการ → รูปตอนตรวจปิด

## รายการ DEFECT: จัดกลุ่ม / เขียนบนรูป

- รายการ DEFECT (ในใบตรวจ หน้ารวม DEFECT และรายงาน) เลือกจัดกลุ่มตาม **ห้อง/พื้นที่** หรือ **หมวดงาน** (หัวข้อ Checklist) ได้ แล้วเรียงตามชื่อ/รหัส DEFECT ในแต่ละกลุ่ม
- เขียนบนรูปด้วย Apple Pencil: ระบบกันฝ่ามือ (นิ้ว/ฝ่ามือที่แตะขณะใช้ปากกาไม่นับ) และไม่สลับข้อมูลจากเซิร์ฟเวอร์ใต้กระดานที่กำลังวาด

## ถ่าย DEFECT ที่หน้างาน

- แท็บ DEFECT ในใบตรวจ: กด **“📷 ถ่าย DEFECT ใหม่ (หน้างาน)”** → เปิดกล้อง ถ่ายแล้วระบบสร้าง DEFECT ให้ทันที (รูปเป็น “ก่อนแก้” ผูกกับ DEFECT นั้น และใส่ห้องจากรายการก่อนหน้าให้) แล้วเปิดหน้ากรอกห้อง/ประเภท/วิธีแก้ · กด **“✓ บันทึก + ถ่าย DEFECT ถัดไป”** เพื่อเปิดกล้องจุดต่อไปทันที
- QC Before/After: **“📷 ถ่าย QC DEFECT ใหม่”** และปุ่ม **“📷 ถ่าย”** ในช่อง Before/After ของหน้าแก้ไข
- ใช้ได้ในโหมดหน้างาน/ออฟไลน์ (รูปเก็บในเครื่องก่อน แล้วส่งขึ้นเมื่อมีสัญญาณ)
- แต่ละการ์ด DEFECT ในแท็บ DEFECT มีช่อง **ก่อนแก้ / หลังแก้** พร้อมปุ่ม **📷 ถ่าย** และ **🖼 อัปโหลด** ของตัวเอง และรูปย่อกดเปิดเพื่อเขียนบนรูปได้

## ปักหมุดแล้วถ่ายรูป + คัดลอก DEFECT
- ปักหมุด DEFECT บนแบบ → เด้งให้ 📷 ถ่าย / 🖼 อัปโหลด ทันที (หรือกด "ข้าม"); ใบส่งปิดจะเป็นรูป "หลังแก้" ถ้ามีรูปก่อนแก้แล้ว
- คัดลอก DEFECT เดิม (ไม่เอารูป/หมุด/ช่องที่ระบายในผัง): ปุ่ม ⧉ ที่การ์ด, "⧉ คัดลอกจาก DEFECT เดิม" ในแท็บ DEFECT, ปุ่มในหน้าแก้ไข, และตอนปักหมุดบนแบบ ("คัดลอก…แล้วปักที่จุดนี้")

## ตาราง DEFECTS LIST OF WORK (หน้า QC)
- หน้า QC → "มุมมอง: ตาราง DEFECTS LIST" แสดงตามแบบฟอร์ม: ลำดับ, พื้นที่, ภาพก่อน, ภาพหลัง, รายละเอียด, Scope งาน, วันที่ตรวจ, กำหนดเสร็จ, ผ่าน/ไม่ผ่าน, ผู้ตรวจ, ผู้รับผิดชอบ, หมายเหตุ (แตะแถวเพื่อแก้ไข)
- ปุ่ม PDF / HTML ในมุมมองตารางจะออกเป็น A4 แนวนอน หน้าละ 3 รายการ แยกหน้าตามอาคาร+ชั้น พร้อมหัว Location / ชั้นที่ / TYPE / โครงการ / วันที่ตรวจ
- ผ่าน = สถานะ "ผ่าน QC ปิดแล้ว", ไม่ผ่าน = "ต้องแก้ไข", "แก้แล้ว รอตรวจซ้ำ" เว้นว่าง
- ฟิลด์ใหม่ในหน้าแก้ไข QC DEFECT: ชั้นที่, Scope งาน, ผู้ตรวจ, ผู้รับผิดชอบ, หมายเหตุ

## แก้: QC DEFECT หายหลังรีหน้า
- สำรองงานลง IndexedDB ของเครื่องทันทีที่แก้ และส่งขึ้นคลาวด์ทันทีเมื่อสลับแท็บ/ปิด/รีหน้า (เดิมหน่วง ~0.7 วินาทีแล้วค่อยสำรอง) งานที่ยังส่งไม่เสร็จจะถูกกู้คืนตอนเปิดใหม่
- ขยับเวอร์ชันแคช (idesk-v2) เพื่อให้เครื่องที่ใช้อยู่ดึงโค้ดใหม่
- แก้เพิ่ม: ข้อมูลสำรองสำหรับเปิดแบบหน้างาน/ออฟไลน์ อัปเดตทุกครั้งที่ส่งงานสำเร็จ (เดิมเก่าค้าง ทำให้รีหน้าแล้วไม่เห็นรายการที่เพิ่งเพิ่ม)
- แก้สำคัญ: โหลดเอกสารจาก Supabase ทีละหน้า 1,000 แถว (เดิมได้สูงสุด 1,000 แถวต่อครั้งโดยไม่เรียงลำดับ เมื่อเอกสารเกิน 1,000 รายการใหม่ๆ จะไม่ถูกโหลดตอนรีหน้า ทั้งที่บันทึกขึ้นระบบแล้ว)

## ใบส่งตรวจ CLOSE: ลบแบบ = ลบ DEFECT ที่ปักหมุดบนแบบนั้น
- ปุ่มลบแบบในใบ CLOSE จะแจ้งจำนวน DEFECT ที่จะถูกลบ (กดยืนยัน 2 ครั้ง) แล้วลบ DEFECT ที่ผูกกับแบบนั้น พร้อมรูปที่ผูกกับ DEFECT และออกจากขอบเขตงาน/ผลตรวจของใบ

## ตาราง DEFECTS LIST ในหน้า DEFECT ตามใบตรวจ + ผ่าน/ไม่ผ่านเลือกได้
- หน้า "DEFECT ตามใบตรวจ": เลือกมุมมอง "ตาราง DEFECTS LIST" (แบบเดียวกับ QC: ภาพก่อน/หลัง, รายละเอียด, ผ่าน/ไม่ผ่าน ฯลฯ) และกด "PDF ตาราง" ส่งออกได้
- ช่อง ผ่าน / ไม่ผ่าน ตั้งได้ในหน้าแก้ไข DEFECT (ทั้ง QC และตามใบตรวจ): ตามสถานะอัตโนมัติ / ผ่าน / ไม่ผ่าน / ไม่ระบุ (เว้นว่าง)
- ปรับ: ค่าอัตโนมัติของ ผ่าน/ไม่ผ่าน ใน QC = "ผ่าน" เฉพาะที่ปิดแล้ว ที่เหลือเว้นว่าง (ยังไม่ตรวจ) จะขึ้น "ไม่ผ่าน" ก็ต่อเมื่อเลือกเอง
- ในใบส่งตรวจ แท็บ DEFECT: เลือก "มุมมอง: ตาราง DEFECTS LIST" ได้ (ผ่าน/ไม่ผ่านอิงผลของรอบนั้น)

## ปรับให้ลื่นขึ้น (ซิงก์ Supabase) + ลบแบบใน CLOSE
- ไม่วาดหน้าใหม่เมื่อ Supabase ส่งข้อมูลที่เราเพิ่งบันทึกเองกลับมา, ไม่วาดหน้าใหม่ขณะกำลังพิมพ์ในช่อง, วาดใหม่แล้วคงตำแหน่งเลื่อนหน้าเดิม
- หน่วงการบันทึกขึ้นคลาวด์ 1.2 วินาที (เดิม 0.7) และสำรองลงเครื่อง 1.5 วินาที; อัปเดตข้อมูลสำรองออฟไลน์ไม่ถี่เกิน 30 วินาที/ตอนซ่อนหน้า (ยังส่งทันทีเมื่อปิด/สลับแท็บ/รีหน้า)
- ลบแบบในใบ CLOSE: จับ DEFECT ที่ปักบนแบบเดียวกันด้วยทั้ง key และภาพแบบ (กรณีแบบถูกเพิ่มใหม่จากคลังแล้ว key ไม่ตรงกับใบ OPEN)

## QC DEFECT: เลือกรูปหลายรูปสร้างหลายรายการ
- ปุ่ม "🖼 เลือกรูปหลายรูป (1 รูป = 1 รายการ)" ในหน้า QC: เลือกรูปพร้อมกันหลายรูป ระบบสร้าง QC DEFECT 1 รายการต่อ 1 รูป (รูปก่อนแก้) ได้เลขที่ต่อเนื่อง และคัดลอกอาคาร/ชั้น/ห้อง/ผู้ตรวจจากรายการก่อนหน้า
- QC มุมมองตาราง = ตารางแก้ไขในตัว: พิมพ์พื้นที่/รายละเอียด/Scope/วันที่/ผู้ตรวจ/ผู้รับผิดชอบ/หมายเหตุ ได้ในช่อง, ปุ่ม "🖼 เพิ่มรูป" เลือกหลายรูปใส่ก่อน/หลังแก้ได้ทันที, ติ๊กผ่าน/ไม่ผ่านในช่อง (ปล่อยว่างทั้งคู่ = ไม่ระบุ)

## ใช้บน iOS เหมือนแอป
- เปิดใน Safari → ปุ่มแชร์ → "เพิ่มลงในหน้าจอโฮม" จะได้ไอคอนและเปิดแบบเต็มจอ (ไม่มีแถบ Safari)
- มือถือ: เมนูหลักอยู่แถบล่างจอ, เคารพขอบจอ/Home bar (safe area), ช่องกรอกใช้ตัวอักษร 16px ไม่ให้หน้าซูมเองเมื่อแตะ, ป๊อปอัปเป็นแผ่นเลื่อนขึ้นจากล่าง, ปิดการเด้งยืดหน้า

## ดีไซน์ใหม่แบบแอปมือถือ (iOS)
- มือถือ: แถบแท็บล่างมีไอคอน (ส่งตรวจ / DEFECT / QC / แบบ / ตั้งค่า), ชื่อหน้าตัวใหญ่, การ์ด/ตารางโค้งมน, สถิติ 4 ช่องเรียงแถวเดียว, ปุ่มหลักลอยมุมขวาล่าง (ส่งตรวจใหม่ / ถ่าย QC DEFECT ใหม่), ป๊อปอัปเลื่อนขึ้นจากล่าง
- จอใหญ่ (คอมพิวเตอร์): หน้าตาเดิม แถบเมนูอยู่ด้านบน
- หมายเหตุ: ห้ามใส่ backdrop-filter/transform ที่ .top เพราะจะทำให้แถบแท็บล่างไปติดกับแถบบน
- ธีมดำ (พื้นดำ + สีส้มนิรภัย) ทั้งมือถือและคอมพิวเตอร์; หน้าแรกบนมือถือ: ทักทายโครงการ, การ์ดสรุป DEFECT ค้างแก้พร้อมวงแหวน % ปิดแล้ว, ทางลัด 4 ปุ่ม (ส่งตรวจใหม่ / ถ่าย QC / แบบหน้างาน / DEFECT)
- QC: กลุ่มไอคอนตามประเภทงาน (Scope) แตะเพื่อกรอง + จัดกลุ่มตามงาน; เครดิต "พัฒนาโดย KRITTANAI" หน้าตั้งค่า

## ขอเข้าห้อง (แท็บ "ขอเข้าห้อง")
- ถ่ายรูปเอกสารขอเข้าห้อง (ถ่ายรูปก่อน) แล้วระบุวันที่ เวลาเข้า/ออก ผู้ขอ/บริษัท และห้องที่ขอ
- กระดานสถานะห้องแบบเรียลไทม์: กำลังใช้ห้อง / รอเข้า / ใช้เสร็จแล้ว / ไม่มีผู้ขอ (รีเฟรชอัตโนมัติทุก 30 วินาที, ขึ้นวันใหม่เองเมื่อข้ามเที่ยงคืน)
- สำรองสถานะรายวันเป็นรูปภาพอัตโนมัติ (หลัง 21:00 หรือเมื่อเปิดแอปครั้งถัดไปหากวันก่อนหน้ายังไม่มี) และกดบันทึกเองได้ ดูย้อนหลังได้ในประวัติ
- หมายเหตุ: การสำรองอัตโนมัติทำงานเฉพาะตอนเปิดแอปอยู่

- ตารางห้องย่อไอคอนให้เล็ก (5 ช่อง/แถวบนมือถือ) รองรับ 20+ ห้อง/ชั้น
- คำขอที่ 'กำลังใช้ห้อง' ถูกล็อก แก้ไข/ลบ/ยกเลิกไม่ได้ จนกว่าจะพ้นเวลาที่ขอ หรือกด 'ออกจากห้องแล้ว'

- แท็บ 'แบบ / ขอบเขต' ในใบส่งตรวจ: รายการแบบเป็น list ย่อ/ขยายได้ทีละแบบ มีปุ่ม 'ขยายทั้งหมด/ย่อทั้งหมด' และป้ายจำนวนโซน/หมุด

- ขอเข้าห้อง: เพิ่มรูป BEFORE ก่อนเข้าห้อง (ถ่าย/เลือกหลายรูป)
- แท็บ 'งานเคลม': รายการเคลม (kind:'claim' ในคอลเลกชัน access) เพิ่มรูปหลายรูป/1 รูป=1 รายการ, หมวดการเคลม, เคลมใคร, อาคาร/ชั้น/พื้นที่, สถานะ, กรอง+จัดกลุ่ม, มุมมองรายการ/ตาราง, ส่งออก PDF
